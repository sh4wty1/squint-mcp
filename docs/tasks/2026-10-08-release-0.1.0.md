# Release 0.1.0 no PyPI (fatia 5)

**Por quê:** fatia 5 do roadmap: `uvx squint-mcp` funcionar para qualquer pessoa.
**O quê:** `squint-mcp` 0.1.0 publicado em https://pypi.org/project/squint-mcp/0.1.0/ (wheel e sdist). Antes do release entrou o fix da issue #4 (PR #10). O README documenta a instalação em dois passos e a configuração em clientes MCP; o CHANGELOG tem a seção `[0.1.0] - 2026-10-08`; o erro de Chromium ausente passou a nomear um comando que existe numa instalação via `uvx`.
**Como:** PR #12 (metadados do pacote, sdist limitado a `src`, `tests` e CHANGELOG, README, CHANGELOG, mensagem de erro em `capture.py`) e PR #13 (`.github/workflows/publish.yml`). A publicação usa trusted publishing do PyPI, sem token: o publisher foi registrado para `sh4wty1/squint-mcp`, workflow `publish.yml`, environment `pypi`. O push da tag `v0.1.0` disparou o upload.
**Verificação:** `pyright`, `ruff check`, `ruff format --check` limpos e `pytest` com 200 passando antes do PR #12; `twine check` nos dois artefatos; pelo wheel local via `uvx`, `ping`, `inspect_element` e `detect_visual_bugs` (4 Findings de `low-contrast-real`, 2 de `text-clipped`); depois do upload, `uvx squint-mcp@0.1.0` vindo do PyPI respondeu 0.1.0 e os mesmos 4 Findings.
**Pendências:** issue #11 (orçamento de pixels por Capture e aliasing da amostragem), que virou a fatia 6; revisar a proposta da v0.2 em `docs/ROADMAP.md`.
