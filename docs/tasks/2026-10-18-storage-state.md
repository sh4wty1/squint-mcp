# Login session from a file (`storageState`), roadmap slice 12

**Por quê:** o Squint abre cada página sem cookies, então uma página atrás de login (o Admin do central-jogos-gc2, sessão num cookie `HttpOnly; Secure; SameSite=Strict; Path=/api/v1/admin`) só é vista como a tela de login. O maintainer pediu a opção 1 (arquivo de sessão) antes da opção 2 (CDP, fatia 13).
**O quê:** fatias 12 e 13 no `docs/ROADMAP.md` (`21a397e`, no main). Plano e checks aprovados (`.specs/features/storage-state/`, `680f16b`). `inspect_element`, `detect_visual_bugs` e `extract_tokens` ganham `storageState`, um caminho absoluto pra um arquivo de storage state do Playwright, carregado num contexto novo a cada chamada e nunca escrito; caminho relativo, arquivo ilegível e arquivo que não é storage state viram `ToolError` sem citar o arquivo (AC 1-13).
**Como:** `capture.capture` lê o arquivo (`_read_storage_state`) e passa ao `browser.new_context(storage_state=...)`; as três tools repassam o parâmetro. Fixture `tests/fixtures/storage-state.html` com API `/api/v1/admin/me` em `tests/conftest.py`; testes em `tests/test_storage_state.py`; três testes de schema existentes ganham `storageState`. README (seção "Pages behind a login"), CHANGELOG (`Added`) e AD-010 em `.specs/STATE.md`.
**Verificação:** `tests/test_storage_state.py` 19 passed; ruff check, ruff format --check (130 arquivos) e pyright 0 erros; scan de bypasses 0 candidatos. Suíte completa em andamento (~45%, sem falhas) no momento deste registro.
