# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Squint stays on 0.x while the Finding schema is still changing: removing or renaming a Finding field, a tool or a tool parameter is a breaking change. Adding a Check or changing a threshold is not breaking, but is always recorded here.

## [Unreleased]

### Added

- `computed` of `inspect_element` holds the colour and the style of each border: `border-*-color` and `border-*-style`, for `top`, `right`, `bottom` and `left`, as Chromium resolves them. The widths stay in `boxModel.border`. A border that paints otherwise than its colour says, such as the `outset` border of a default `<button>`, can now be explained from Squint alone. Every Capture reads the four border styles too ([#32](https://github.com/sh4wty1/squint-mcp/issues/32)).
- `storageState` on `inspect_element`, `detect_visual_bugs` and `extract_tokens`: the absolute path of a Playwright storage state file, such as the one `playwright codegen --save-storage` writes, opens the page as that login session sees it, with its cookies and `localStorage`. Each call loads it into a fresh context and never writes it. A relative path, a file that cannot be read and a file that is not a storage state are errors, and no error quotes the file. `sessionStorage` is not carried.
- `extract_tokens` tool: for a page (`url`, optional `scope`, optional `viewport`), returns the design tokens it uses in eight Families (`colors` by role, font families, font sizes, font weights, line heights, `spacing` by role, `radii`, `shadows`), each token with how many elements use it and in which role, and whether the page stabilized. A `scope` narrows the reading to the elements a selector matches and everything under them. Colours whose ΔE2000 is below 2 and lengths less than 1px apart are one token, with its `variants`. Each Family returns at most its 20 most used tokens, with the `total` it found. Only elements that paint a box, are visible and are not under an opacity of 0 are read. Every Capture now reads twelve more computed properties (the border colours, the corner radii, `box-shadow`, `text-shadow`, `row-gap` and `column-gap`) and which margins are `auto`, for every tool: the collector takes 12% to 27% longer.
- `offscreen-overflow` Check: on a page that scrolls horizontally, reports the element that sets the width of the page, one per viewport, with by how many pixels the page passes the viewport. Its severity is always `major`. It reports nothing while the page hides its horizontal overflow (`overflow-x: hidden` or `clip` on `html` or `body`), and nothing on a right-to-left page.
- `overlap` Check: reports text that another element is painted over, text painted over text included. The Finding sits on the covered text and carries the share of its ink that is hidden, read from the pixels (`hiddenPercent`), and the selector of the element that covers it (`coveredBy`), which works in `inspect_element`. A text is reported from 10% hidden; from 25% the Finding is `major`, below that `minor`. The severity is one level lower, `minor` or `info`, when the cover is in a raised layer: the cover, or an ancestor of it that does not also hold the text, is positioned with a `z-index` above 0. It is the first use of `info`. It does not report what is covered by a layer that declares itself (an element with a `role` of `menu`, `listbox`, `tooltip`, `dialog` or `alertdialog`, an open `dialog` element, an open popover, or anything inside one of them) or by a `fixed` or `sticky` element. Nor does it report a cover that paints nothing over the text (a link stretched over its card, an element of `opacity: 0`) or that lets at least half of the ink through, a cover that hit testing does not give (`pointer-events: none`), or text covered by one of its own descendants. Known limits: text on or inside an element with `mix-blend-mode` can go unreported; so can text under a pseudo-element that an element paints outside its own box, when that element is itself covered; text under a cover whose `backdrop-filter` changes colours is reported though it can be read; and on a page that moves when it is scrolled `coveredBy` can be wrong or the Finding missing. A call that runs it takes about twice as long per viewport; a call whose `checks` leaves it out does not pay for it.
- `font-fallback` Check: reports a web font that the page declares and that did not load, when text is rendered in a fallback font because of it. There is one Finding per family, on the first element in document order whose text falls back, and it carries the name of the family (`family`), how many elements render their text in a fallback (`elements`) and the width of the text of that element set on one line (`textWidthPx`). Its severity is always `minor`. Only the first family of an element's `font-family` is judged, and only when the page declares it, in an `@font-face` rule or from a script: a family that failed and comes after the first is one of the fallbacks the CSS names, and is not reported. An element counts when its text is as wide in its `font-family` as without the first family, so text in a face of the family that did load, of another weight or style, is not counted. It does not report a family that is only named, as the fonts of a system stack that are not on the machine are; a font that loaded and is not used, as with `font-display: optional` when the font answers late; a font that failed and that no text asks for; text of pseudo-elements, so an icon font used through `::before` gets no Finding when it fails; or text of `visibility: hidden`. Known limits: a text of which only some glyphs fall back is not reported, and the Finding of a family that failed and has the name of a font installed on the machine can change from one machine to the next.

### Changed

- Text is rasterized in grayscale in every Capture: Chromium is launched with `--disable-lcd-text`. With subpixel text the same glyph is painted differently over different backdrops, so the ink of a text could not be compared between two renders of a page. Where Chromium used subpixel text, as on Windows, the edges of glyphs lose their colour fringe: crops, `sampledColors` and the contrast of a text can differ slightly from 0.1.0.
- The `low-contrast-real` Check stays fast on a page of many texts painted over millions of colours: it counts at most 262,144 pixels (512x512) across the texts of a page at one viewport, where the limit was per element. A text small enough is still counted whole; the larger ones share what is left equally, so on a page with more text than that their contrast comes from a sample, and a text of very little ink may not be judged on such a page ([#11](https://github.com/sh4wty1/squint-mcp/issues/11)).
- A sampled region no longer loses a colour of a 1px or 2px pattern, such as stripes or a checkerboard: `inspect_element` and `low-contrast-real` pick its pixels at varying offsets instead of at a regular step. The offsets are the same on every call, so the result of a call does not change from one run to the next; the `sampledColors` shares and the contrast of a sampled region differ slightly from 0.1.0 ([#11](https://github.com/sh4wty1/squint-mcp/issues/11)).

### Fixed

- `font-fallback` reports a family whatever characters its name holds: a backslash, quotation marks or apostrophes, whitespace at its edges or doubled (U+00A0 included), and characters that Chromium serializes with hexadecimal escapes, such as a tab. A failed family that a script adds with a name that needs quoting, such as `new FontFace("Script Face", ...)`, is reported too, under its name without quotes. Known limit: a failed `@font-face` family whose name reads as a quoted one, such as `"Quoted"` with its quotation marks, is also matched to text that asks for `Quoted` ([#20](https://github.com/sh4wty1/squint-mcp/issues/20)).
- A screenshot that Chromium hands back with a part of the page not painted yet is no longer read as a page with nothing there. On a page with several layers of its own (sticky elements, faded texts, links with a `z-index`), a text beyond the viewport could have no ink in one of the pictures a Capture compares, and lose its Finding on some calls and not on others. A Capture now lets the page paint two frames before each screenshot, and waits for them 250ms at most: a page that never calls an animation frame back is captured all the same. A call takes up to a fifth longer.
- The layout of a Capture on a page that uses the generic `monospace` font on Windows. The first screenshot that reached beyond the viewport made Chromium change that font and lay the page out again, so boxes were read from one layout and pixels from another, in every tool. A Capture now settles the layout before it measures anything ([#18](https://github.com/sh4wty1/squint-mcp/issues/18)).

## [0.1.0] - 2026-10-08

First release, on PyPI as `squint-mcp`.

### Added

- MCP server over stdio, started with the `squint-mcp` command.
- `ping` tool: returns the server name and version and echoes an optional `message`.
- `inspect_element` tool: for one element of a page (`url`, `selector`, optional `viewport`), returns its computed styles, box model, the colours sampled from its pixels, whether the page stabilized, and a crop.
- `detect_visual_bugs` tool: for a page (`url`, optional `viewports`, optional `checks`), runs Checks on one Capture per viewport and returns Findings ordered by severity, whether each viewport stabilized, and up to five crops. Each Finding carries a selector that is unique on the page and works in `inspect_element`.
- `text-clipped` Check: reports text cut off horizontally by its own box (`overflow-x: hidden` or `clip`), confirmed in the pixels. A cut of 8px or more is `major`, a smaller one `minor`; a cut of 1px is not reported.
- `low-contrast-real` Check (WCAG 2.2 SC 1.4.3): reports text whose contrast is below 4.5:1, or 3:1 for large text (24px, or 18.66px bold), against the background painted behind it. The background is sampled from the pixels, so it is right over an image or a gradient; where it varies, the worst tenth of the text decides. A ratio under 3:1 is `major`, any other `minor`. Text with an `opacity` below 1, on itself or on an ancestor, is not judged.
- `evidence.measured` of a Finding can hold strings besides numbers: `low-contrast-real` reports `textColor` and `sampledBackground` as `#rrggbb`.
- Findings of the same severity and viewport come in document order whatever the Check that reported them, and two Findings on one element in the order of their Check names. The order of `checks` does not change the result.
- `inspect_element` and the `low-contrast-real` Check stay fast on a large element painted in millions of colours, such as a long photo-heavy page: an element, or the text of an element, of more than 262,144 pixels (512x512) is sampled down to that many before its colours are counted, so `sampledColors` and the contrast of such an element come from the sample. Smaller ones are counted whole, as before ([#4](https://github.com/sh4wty1/squint-mcp/issues/4)).
